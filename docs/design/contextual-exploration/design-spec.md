# F-012 街区探索与情境对话：视觉与交互规格

更新时间：2026-09-22

状态：`USER_UAT_PASSED_PENDING_REAL_PROVIDER_UAT`

## 设计目的

玩家在场景中查看固定地标时，应先理解“看到了什么、可以和谁讨论、是否要记下”，再决定是否把这个发现带入 NPC 对话。观察卡只呈现确定性的作者文本，不调用模型、不写长期记忆，也不自动发送消息。

## 首个正常状态

- 逻辑视口：640×360，保持项目现有整数倍缩放和像素稳定性。
- 场景：暖色傍晚的暮光街区，玩家位于入口导览区域，Nia 和导览点保持可见。
- 最近目标提示：`E  查看暮光导览牌`。
- 观察卡位置：视口右上至中部，不遮挡顶部连接状态、街区标题、左侧玩家与 Nia，也不占用底部交互提示区域。
- 信息顺序：`街区发现` 类别 → `暮光导览牌` 标题 → 固定观察正文 → `可带去和 Nia 讨论` 归属 → `关闭 Esc` / `记下话题` 操作。
- 正文：`导览牌标出一条只在傍晚亮起的夜市灯带。`

## 视觉规则

- 复用现有中文字体、深紫半透明底、暖橙标题和像素边框。
- 观察类信息使用青绿色边框与类别标签，与既有对话面板的暖橙边框区分。
- 正文在 640×360 下无需滚动即可完整阅读。
- 两个按钮沿用现有按钮状态，不增加外部美术、肖像或新字体。
- 观察卡与对话面板、话题与记忆弹层互斥显示。

## 交互契约

- 打开观察卡后暂停玩家移动。
- `关闭 Esc` 与 Esc 均关闭且不记录发现。
- 只有选择 `记下话题` 才写入当前游戏启动期的本地发现状态。
- 记下后，对应 NPC 的话题菜单才显示 `讨论街区发现`；该入口只填入可见、可编辑的自然语言草稿。
- 本规格的首张截图只验证正常状态的信息层级，不证明关闭、记录、重开或对话接入已经实现。
